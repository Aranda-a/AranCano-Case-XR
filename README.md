# AranCano · 游戏化蚊子包交互（XR 主路径）

**角色标签：** 产品原型 · 交互设计 · XR 空间交互 · 陪伴型 IP（Annno）

**产品定位：** 在痒觉与焦虑并发的急性期，提供轻量且具备明确闭环的干预方案：对准真实患处完成一局微交互，将生理烦躁转化为可揉捏、可归档的具身体验。它解压的是陷入抓挠冲动的手；阻断的是破坏性的二次抓挠循环，而非压抑第一下的生理本能。

**最终产品定位：** 一款将真实蚊子包转译成可按压 3D 关卡的 XR 游戏化交互原型。

**核心创新：** 自研本地视觉识别流程，将真实红肿区域转译成具有不同质感和体量的 3D 交互替身，再通过 XR 空间贴附，把抓挠冲动变成一局可以按完的游戏化交互。

```text
真实皮肤信号 → 视觉计算 → 3D 角色映射 → XR 空间贴附 → 游戏化按压反馈
```

**验证边界：** 反复抓挠的痛点能站住；下次被咬自觉想起来用，是下一阶段的触发，不在本阶段证明范围内。

独立完成的 0–1 摄像头空间交互原型。当前用微信完成真机验证；对准、按压、收束这一套不绑死在小程序上。问题定义、主路径、多通道反馈与验证口径由创作者负责。需求梳理阶段用洞察 skill 辅助检索与推导；问题是否成立、验证边界由创作者判断。开发与文档另用 AI 辅助。本页展示决策与结果。详见 [产品说明](docs/CASE-STUDY.md)。

**怎么读：** 约 30 秒先看下方有声主片（C）与 GIF → 约 2 分钟看问题、路径取舍与数据卡 → 细节见故事板折叠 · [验证计划](docs/VALIDATION.md) · [METRICS.md](docs/METRICS.md)

### 从真实红肿，到可按压的 3D 关卡

AranCano 不是随机生成一个模型盖在相机画面上。

大白话解释：用户先把疑似蚊子包放进瞄准框，小程序会在设备本地看看这块区域相对周围皮肤有多红、红色范围有多明显、红肿大致集中在哪里，再生成只用于交互映射的产品代理分数。

这些结果不用于医学判断，而是决定这次出现什么样的 3D 替身：

- 偏轻、偏柔和的结果，映射为更接近软面团质感的 3D 包子；
- 偏红、偏明显的结果，映射为更有弹性的 3D 果冻；
- 分析结果还会影响模型的颜色、体量和初始观感。

随后，XR 主路径会把这个 3D 替身尽量放回真实目标附近。用户移动手机观察时，模型会产生空间视差；长按时，形变、声音和振动共同表达按压进度，直到模型塌陷并完成封印。

```text
对准真实红肿区域
→ 本地视觉分析
→ 生成包子 / 果冻预设
→ XR 空间贴附
→ 长按形变
→ 塌陷封印
```

当前原型不判断目标是否一定为蚊子包，也不作医学意义上的炎症或肿胀分级。图像默认在设备本地流程中处理；公开仓不披露算法阈值、映射公式与完整调参样本。

## 2. 要解决什么

### 常见问题

「涂药或忍一下就好，为什么还要开小程序？」

**药膏靠清凉感压制痒觉，而这个产品顺应本能：它不拦你下意识挠第一下，但防的是反复抓挠破皮。在你手还想再抓、最烦躁的那几十秒，让你对准真蚊子包玩完一小局，把破坏欲安全地代偿掉。**

**抓可能短暂压住痒，也可能抓破皮、加重循环（[研究](https://www.nature.com/articles/nn.2292) · [综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC6502296/)）——所以给的是好玩的解决方案，不是疗效声明。**

当场能否走完看数据卡；人已经在反复抓、还想再抓时会不会改去做完这一局，另用日记法，见 [验证计划](docs/VALIDATION.md)。不把它当成「被咬第一下会不会打开」。

这一局怎么好玩：

| 目标 | 做法 |
|------|------|
| 有对象 | 蚊子包变成可按的火山包子 / 火山果冻；Annno 陪伴，不抢主角 |
| 有进度 | 形变、声音、振动随按压力度变化；松手回弹 |
| 有终点 | 塌陷 + 封印表示做完；月历可回看，不用积分留人 |

<details>
<summary><strong>入口步骤更多，如何设计</strong></summary>

对准与长按比「再抓一下」多几步，被设计成这一局的一部分：默认只走一条主路，失败再进退路，避免痒烦时还要选版本。

| 摩擦点 | 设计 | 如何验证 |
|--------|------|----------|
| 比再抓一下多几步 | 微信直达；默认 C，失败走 A；靠好玩和解压感把人从循环里接走 | 数据卡看完成率（场内走完，不证明自己会进来） |
| 需要对准 | 对准是认出这个包、开这一局，不是强制放手 | 引导说明出模与真包的关系 |
| 循环中段会不会改做完 | 封印、月历、批语留下「这一轮结束了」；不用排行榜或连续登录 | 机制已落地；会不会从「还在抓」切进来，另按日记法观察 |

</details>

<details>
<summary><strong>与常见选择对照</strong></summary>

| 选择 | 为何会选 | 优势 | 局限 |
|------|----------|------|------|
| 抓、掐、搓 | 本能、即时 | 最快、当下就爽 | 停不下来；也可能伤皮肤 |
| 花露水、药膏等 | 处理生理不适 | 熟悉 | 起效因产品而异；涂完手仍可能想动 |
| 热敷、止痒器具等 | 用其他刺激盖过痒 | 触感明确 | 需额外携带 |
| AranCano | 给正在一直抓的手一个能玩完的解决方案 | 微信内可用；形变 + 声 + 振；单主路 + 退路 | 步骤多于再抓一下，不和第一抓抢；进场发生在循环中段，与当场完成率分开验证 |

</details>

## 3. 为何默认 C、保留 A

| 轨道 | 优先保证 | 主要代价 | 角色 |
|------|----------|----------|------|
| **A 轻量平面** | 能打开、能按完 | 更偏贴片感 | 兼容退路 |
| **B 跟手立体** | 跟随红斑 | 易与背景分离、漂移 | 对照，不进默认入口 |
| **C 立体跟包** | 钉在空间中，转手机有视差 | 进场依赖平面识别，设备有差异 | **默认主路径** |

跟手更紧，不等于观感更真。B 一旦迟滞，模型容易和实景脱节。C 把风险集中在进场：可能失败一次，但失败可解释、可重试，并可退到 A。空间能力不足时走 A。

真机反馈里，有人觉得 C「更像贴在包上」，也有人感知到进场等待——这与「默认 C、失败退 A」一致。更多说明见 [产品说明](docs/CASE-STUDY.md)。

锁定后分两种情况：

1. **手机在动、包基本不动** → 用世界锚稳住模型  
2. **包换了位置** → 用户点「微调贴位」再锁；失败则保持原位  

### 试用反馈如何影响设计（已脱敏）

- 「冒出个能点的东西，不知道和我的包有什么关系。」→ 引导需说明出模与真包的对应；对准是这一局的第一步。  
- 「放大方向别扭，俯视时更明显。」→ 操作方向需贴合持机姿势。  
- 「只有包在动，和背景割裂。」→ 跟手路径易分家；**因此 B 不进默认入口**，默认走 C、B 仅作对照。

## 4. 轻量数据卡

埋点 → 体验版上报 → 按入选口径计入有效样本 → 汇总三指标。

| 指标 | 数值 | 口径 |
|------|------|------|
| 完成率 | 100% | **入选：** 有本局小结的体验版会话；**计完：** 按满并封印；**n=15** |
| 想挠分数前后变化 | ↓45.9 | 滑杆 0–100（不太想挠 → 很想挠）。数值是玩前减玩后的平均：这 8 人玩完一局后，还想抓挠的程度平均低了 45.9。只计入玩前、玩后都认真拖过的人（与完成率分套）。当场自评，不是疗效。 |
| 退到轻量 A | 0 次 | 与完成率同一批入选会话；**n=15** |

**结论：** 这 15 局默认走 C 都按完了，没有人落到 A。说明这批真机上 C 够用；A 仍是退路——C 不稳或不好用时才会进去。不是 A 用不到。见 [METRICS.md](docs/METRICS.md)。
