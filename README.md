# AranCano · 互动产品说明

> 将短暂的皮肤烦躁，转译成一个可以完成、可以停止的摄像头按压闭环。

AranCano 是一个微信小程序交互原型。用户对准真实蚊子包后，屏幕生成可按压的视觉替身；持续按压会驱动模型形变、声音、振动和界面反馈，最终以塌陷和封印完成收束。

产品是一套**行为替代交互原型**：用空间贴附、长按和多通道反馈，接住「知道不该抓，手还是想动」的那几秒。

本页重点展示游戏化产品思维、空间交互取舍与多通道反馈设计。它不提供诊断、治疗或止痒效果承诺。

> 为保护用户隐私与原创方案，本公开仓不包含产品源码、算法参数、坐标映射、完整决策记录、原始访谈、真实用户照片及未发布资产。

## 1. 产品问题

短暂但反复出现的抓挠冲动，缺少一个有反馈、能完成、也能结束的替代动作。

### 为什么这不只是一个好玩的点子

最直接的质疑是：被蚊子咬了，抹药或者忍一下就好，为什么还要打开小程序？

这个问题成立，所以 AranCano 不和药物争「治疗」。它处理的是另一个更短的窗口：痒出现后，手会立刻去抓、掐或搓。研究显示，抓挠确实能短暂抑制由痒引起的神经传递；但反复抓挠也可能破坏皮肤屏障，继续加重「越痒越抓、越抓越痒」的循环。[相关研究](https://www.nature.com/articles/nn.2292) · [机制综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC6502296/)

因此，产品假设不是「用手机治痒」，而是：

> 当手已经想做点什么时，能否给它一个有反馈、但不直接抓伤皮肤的替代动作？

这个假设仍要由真实使用验证。走完整个演示，只能证明交互可用；下一次痒时是否会主动打开，才更接近需求成立。

### 我们在和谁争夺这只手

| 现有选择 | 为什么会选它 | 优势 | 代价或空缺 |
|----------|--------------|------|------------|
| 抓、掐、搓 | 本能、立刻有感觉 | 最快、触感最强 | 可能破坏皮肤，容易进入抓挠循环 |
| 花露水、药膏等 | 处理生理不适 | 熟悉、直接 | 起效时间因产品而异；涂完以后手仍可能想抓 |
| 热敷、止痒器具等 | 用额外刺激覆盖痒感 | 触感明确 | 需要随身携带额外物品 |
| AranCano | 让手有事可做，并给出完成信号 | 微信内进入；形变、声音、振动一起反馈 | 比直接抓挠多几步；主动打开意愿仍需验证 |

### 产品代价怎么接

「比直接抓挠多几步」和「下次还会不会打开」，是同一类风险：入口摩擦。处理方式不是假装没有摩擦，而是让多出来的步骤变成替代动作本身，并尽量缩短决策负担。

| 代价 | 产品怎么接 | 还要验证什么 |
|------|------------|--------------|
| 比抓挠多几步 | 微信内直接进入；默认只走主路径 C，失败再给退路 A，不让用户在痒的时候挑三轨 | 从打开到第一次按压，步骤是否仍过多 |
| 对准像额外负担 | 把「对准」设计成把手从皮肤移开的第一步，而不是可有可无的前置 | 对准是否被理解成任务，还是被理解成打扰 |
| 主动打开意愿未知 | 用短闭环和封印做一次可完成的记忆点；不靠排行榜或连续登录硬推留存 | 无人提醒时，下次痒会不会真的打开 |

项目没有用积分和排行榜延长使用，而是设计了一条短闭环：

```
对准真实目标 → 生成视觉替身 → 持续按压 → 满格塌陷 → 获得封印
```

判断体验是否成立，主要看三个结果：

- 替身是否像是贴在真实目标上
- 按压是否具有连续、可信的反馈
- 满格之后是否形成明确的结束感

## 2. 游戏化闭环

游戏化在这里承担三项职责：

### 目标化

把模糊的烦躁转译成一个可见、可操作的对象。真实蚊子包变成可按压的火山包子或火山果冻；Annno 负责陪伴和反馈，不抢走主角位置。

### 进度化

通过视觉形变、声音和振动建立持续增强的蓄力过程。用户要一直按住，进度才往前走；提前松手会回弹，所以「用力」不是点一下就过。

### 终点化

用塌陷和封印建立清楚的完成信号，而不是诱导无限游玩。

封印是完成凭证，不是金币或竞争排名；记录用于回看，不制造连续登录压力。

这一条短闭环对应的产品判断是：

> 游戏化不是加积分，而是把「抓一下」改写成「对准 → 按住 → 按满 → 收束」。完成即离开，才算把冲动接住了。

## 3. 多通道反馈

长按不是单一进度条，而是视觉、听觉、触觉三条主通道一起走的同一条曲线；文案只解释当前状态和下一步，不另开玩法。

- **视觉**：模型逐步变形、向外铺开
- **听觉**：按压质感逐步增强，满格出现独立高潮
- **触觉**：振动由轻到密，再在收束时加重

三条主通道表达同一个按压进度，避免用户看到、听到和摸到的节奏彼此冲突。

现实中的「按一下」，被拆成三个连续阶段：

1. **刚按上**：模型开始受压，触觉确认「按到了」
2. **持续按住**：模型向外铺开，声音与振动随进度增强
3. **按满收束**：塌陷、较强触觉与结束音效共同出现，随后进入封印

实现由按压进度驱动，不是固定的一秒动画。主路径约数秒按满；不同轨道手感节奏可以不同，但都共用「按住才前进、松手回弹、按满才收束」这一套规则。

## 4. 三种空间策略

项目只有三条轨道：A、B、C。它们解决同一个产品任务，区别在于如何分配误差与工程成本。

### A · 轻量平面

优先兼容与稳定完成。代价是深度有限，更容易出现贴片感。产品角色：空间能力不可用时的退路。

### B · 持续跟随

优先响应目标移动。代价是延迟和抖动会持续暴露，模型可能与相机背景产生割裂。产品角色：跟手对照，不是默认主路径。

### C · 空间贴附

优先镜头运动下的空间一致性。模型落在世界锚点上：手机靠近、俯视、侧看时，替身与真实目标保持同一空间关系，而不是贴在屏幕上跟着画面漂。

风险集中在进入阶段，包括初始化与设备兼容。目标真的换了位置时，不靠持续自动跟红硬追，而是提示用户点「微调贴位」，主动校正一次。

### 为什么暂定选 C

| 步骤 | 表述 |
|------|------|
| 冲突 | 跟得更紧，不等于贴得更真。B 每次迟滞，都会暴露模型与相机背景不在同一空间。 |
| 证据 | 真机体验与用户反馈更偏好 C 的空间稳定；同时，C 的进入失败更集中、也更显性。 |
| 取舍 | 把全程持续、难以忽视的漂移，换成进入时一次可解释、可重试、可降级的失败。 |
| 决策 | C 暂定主路径；A 做兼容退路；B 保留为跟手对照。这是配对可用性验证，不是随机分流实验。 |
| 验证 | 用同一用户比较空间贴合、完成时长、重试率、偏好与不适感，再决定是否固化。 |

选择 C 之后，工程上把「稳定」和「目标移动」拆成两件事：

1. **镜头在动、目标大致不动**：世界锚点负责稳住模型。用户转角度、靠近或拉开时，替身不应乱飘，否则「我正在按这一个包」的因果感会断。
2. **真实蚊子包换了位置**：系统提示「位置变了？点微调贴位重新贴住」。用户确认后，再按当前框内目标重新锁定；检查不过或失败时，保持原位置，不擅自乱跳。

这样包装的产品判断是：

> 自动跟红追求的是「模型永远黏着皮肤」；世界锚点追求的是「模型待在同一个地方，等我按」。短闭环里，后一种更像把包按平；目标真的挪走了，再交给用户一次清楚的校正，比全程抖动更可控。

完整决策与产品过程见 [产品说明](docs/CASE-STUDY.md)。

## 5. 主路径之外

- 空间能力不可用时仍能完成核心闭环
- 页面隐藏、重扫和返回时终止媒体与异步任务
- 用户图像默认在本地流程内处理
- 历史方案保留为决策证据，但不进入公开产品包
- 决策记录包含证据、限制与回退条件
- 三维资产有可重复的轻量化流程：模型简化、纹理尺寸控制、底面中心校正，再输出给小程序
- 性能验证按机型分档记录启动、出模、按压流畅度和失败退路；达到统一基线后再对外给数字

当前仍是真机验证期原型，空间稳定性、设备差异和多通道反馈强度需要继续测试。
