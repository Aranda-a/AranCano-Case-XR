# AranCano · 互动产品说明

> 将短暂的皮肤烦躁，转译成一个可以完成、可以停止的摄像头按压闭环。

AranCano 是一个微信小程序交互原型。用户对准真实蚊子包后，屏幕生成可按压的视觉替身；持续按压会驱动模型形变、声音、振动和界面反馈，最终以塌陷和封印完成收束。

它不是数字药水，而是一套**行为替代交互原型**：尝试用空间贴附、长按和多通道反馈，接住「知道不该抓，手还是想动」的那几秒。

本页重点展示游戏化产品思维、空间交互取舍与多通道反馈设计。它不提供诊断、治疗或止痒效果承诺。

> 为保护用户隐私与原创方案，本公开仓不包含产品源码、算法参数、坐标映射、完整决策记录、原始访谈、真实用户照片及未发布资产。

## 1. 产品问题

短暂但反复出现的抓挠冲动，缺少一个有反馈、能完成、也能结束的替代动作。

### 为什么这不只是一个好玩的点子

最直接的质疑是：被蚊子咬了，抹药或者忍一下就好，为什么还要打开小程序？

这个问题成立，所以 AranCano 不和药物争「治疗」。它处理的是另一个更短的窗口：痒出现后，手会立刻去抓、掐或搓。研究显示，抓挠确实能短暂抑制由痒引起的神经传递；但反复抓挠也可能破坏皮肤屏障，继续加重「越痒越抓、越抓越痒」的循环。[相关研究](https://www.nature.com/articles/nn.2292) · [机制综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC6502296/)

因此，产品假设不是「用手机治痒」，而是：

> 当手已经想做点什么时，能否给它一个有反馈、但不直接抓伤皮肤的替代动作？

这个假设仍要由真实使用验证。走完整个演示，只能证明交互可用；下一次痒时是否会主动打开，才更接近需求成立。

### 我们在和谁争夺这只手

| 现有选择 | 为什么会选它 | 优势 | 代价或空缺 |
|----------|--------------|------|------------|
| 抓、掐、搓 | 本能、立刻有感觉 | 最快、触感最强 | 可能破坏皮肤，容易进入抓挠循环 |
| 花露水、药膏等 | 处理生理不适 | 熟悉、直接 | 起效时间因产品而异；涂完以后手仍可能想抓 |
| 热敷、止痒器具等 | 用额外刺激覆盖痒感 | 触感明确 | 需要随身携带额外物品 |
| AranCano | 让手有事可做，并给出完成信号 | 微信内进入；形变、声音、振动一起反馈 | 比直接抓挠多几步；主动打开意愿仍需验证 |

项目没有用积分和排行榜延长使用，而是设计了一条短闭环：

```
对准真实目标 → 生成视觉替身 → 持续按压 → 满格塌陷 → 获得封印
```

判断体验是否成立，主要看三个结果：

- 替身是否像是贴在真实目标上
- 按压是否具有连续、可信的反馈
- 满格之后是否形成明确的结束感

## 2. 游戏化闭环

游戏化在这里承担三项职责：

### 目标化

把模糊的烦躁转译成一个可见、可操作的对象。

### 进度化

通过视觉形变、声音和振动建立持续增强的蓄力过程。

### 终点化

用塌陷和封印建立清楚的完成信号，而不是诱导无限游玩。

封印是完成凭证，不是金币或竞争排名；记录用于回看，不制造连续登录压力。

## 3. 多通道反馈

长按不是单一进度条，而是一条共同的反馈曲线：

- **视觉**：模型逐步变形、铺开，环境反馈随之收束
- **听觉**：按压质感逐步增强，满格出现独立高潮
- **触觉**：振动由稀疏变得更明确
- **信息**：文案只解释状态和下一步动作

四个通道表达同一个进度，避免用户看到、听到和摸到的节奏彼此冲突。

现实中的「按一下」，被拆成三个连续阶段：

1. **刚按上**：模型开始受压，触觉给出轻反馈
2. **持续按住**：模型向外铺开，声音与振动随进度增强
3. **按满收束**：塌陷、较强触觉与结束音效共同出现，随后进入封印

实现以按压进度而不是固定的「一秒动画」驱动；不同玩法路径约需数秒完成。这样既保留用户的主动控制，也避免用未经实测的毫秒数字包装手感。

## 4. 三种空间策略

三条轨道解决的是同一个产品任务，区别在于如何分配误差与工程成本。

### 甲 · 轻量平面

优先兼容与稳定完成。代价是深度有限，更容易出现贴片感。

### 乙 · 持续跟随

优先响应目标移动。代价是延迟和抖动会持续暴露，模型可能与相机背景产生割裂。

### 丙 · 空间贴附

优先镜头运动下的空间一致性。风险集中在进入阶段，包括初始化与设备兼容。

当前暂定贴附为主路径。依据不是「技术越新越好」，而是：

> 一次可解释、可重试、可降级的进入风险，比互动全程持续发生的空间漂移更容易被接受。

轻量平面保留为兼容退路，跟随保留为产品对照。当前属于配对可用性验证，不是随机分流实验。

这三条不是自动逐级切换的「三级技术栈」：空间贴附是当前主路径，轻量平面是失败退路，持续跟随是开发阶段保留的体验对照。这样的角色划分，避免把工程实验误写成用户要理解的三套玩法。

完整决策与产品过程见 [产品说明](docs/CASE-STUDY.md)。

## 5. 主路径之外

- 空间能力不可用时仍能完成核心闭环
- 页面隐藏、重扫和返回时终止媒体与异步任务
- 用户图像默认在本地流程内处理
- 历史方案保留为决策证据，但不进入公开产品包
- 决策记录包含证据、限制与回退条件
- 三维资产有可重复的轻量化流程：模型简化、纹理尺寸控制、底面中心校正，再输出给小程序
- 性能验证按机型分档记录启动、出模、按压流畅度和失败退路；达到统一基线后再对外给数字

当前仍是真机验证期原型，空间稳定性、设备差异和多通道反馈强度需要继续测试。
